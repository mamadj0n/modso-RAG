    ###‌ خلاصه‌ای از سازوکار سیستم‌های جستجوی تصویری
    
    جستجوی تصویری (Image Search) به فرآیند یافتن تصاویر مشابه یا مرتبط با یک تصویر ورودی یا یک توصیف متنی می‌گوید. این کار معمولاً در چند لایهٔ اصلی انجام می‌شود:
    
    مرحله: ۱. استخراج ویژگی (Feature Extraction)
    توضیح: تصویر به نمایهٔ عددی (vector) تبدیل می‌شود که معنای محتوا را حفظ می‌کند.
    ابزار / الگوریتم‌های رایج: - شبکه‌های پیش‑آموز CNN (ResNet, EfficientNet) <br> - مدل‌های ترکیبی Vision‑Language مثل CLIP, ALIGN <br>
      - استخراج SIFT / SURF برای روش‌های کلاسیک
    ────────────────────────────────────────
    مرحله: ۲. فشرده‌سازی / نرمال‌سازی
    توضیح: بردارهای استخراج‌شده معمولاً طول زیادی دارند؛ برای سرعت جستجو آنها را فشرده یا نرمال می‌کنیم.
    ابزار / الگوریتم‌های رایج: - PCA, FAISS IVF, HNSW (مانند کتابخانهٔ FAISS, Annoy)
    ────────────────────────────────────────
    مرحله: ۳. ایندکس‌سازی (Indexing)
    توضیح: بردارهای همهٔ تصاویر در دیتابیس در یک ساختار داده‌ای ذخیره می‌شوند که امکان جستجوی سریع را فراهم می‌کند.
    ابزار / الگوریتم‌های رایج: - FAISS (IVF‑Flat, IVF‑PQ, HNSW) <br> - Milvus, ElasticSearch + dense vectors, Pinecone
    ────────────────────────────────────────
    مرحله: ۴. پردازش پرس‌وجو (Query Processing)
    توضیح: دو حالت اصلی وجود دارد: <br>• Query‑by‑Image: تصویر کاربر نیز به همان روش استخراج ویژگی می‌شود. <br>• Query‑by‑Text: متن به
      بردار متنی (معمولاً توسط همان مدل Vision‑Language) تبدیل می‌شود.
    ابزار / الگوریتم‌های رایج: - برای متن: توکنایزر BPE + encoder متن (مانند CLIP‑text encoder)
    ────────────────────────────────────────
    مرحله: ۵. محاسبه شباهت (Similarity Computation)
    توضیح: شباهت بین بردار پرس‌وجو و بردارهای ایندکس‌شده با معیارهای فاصلهٔ برداری (cosine similarity, L2 distance) محاسبه می‌شود.
    ابزار / الگوریتم‌های رایج: - محاسبهٔ cosine similarity یا inner product در فضای بردارها
    ────────────────────────────────────────
    مرحله: ۶. رتبه‌بندی و بازگشت نتایج
    توضیح: نتایج بر اساس مقدار شباهت مرتب می‌شوند؛ ممکن است فیلترهای اضافی (برچسب‌ها، تاریخ، منبع) هم اعمال شود.
    ابزار / الگوریتم‌های رایج: - Top‑K retrieval (مثلاً 10 یا 100 تصویر برتر)
    ────────────────────────────────────────
    مرحله: ۷. بهبود (Re‑ranking) و فیدبک
    توضیح: برخی سامانه‌ها پس از دریافت نتایج اولیه، با استفاده از فیدبک کاربر (کلیک/نپسند) مدل را دوباره تنظیم می‌کنند یا از تکنیک‌های
      Rerank (مثلاً مدل‌های BERT) استفاده می‌کنند.
    ابزار / الگوریتم‌های رایج: - Learning‑to‑Rank, Rerankers بر پایه ترنسفورمرها
    
    
    
    جزئیات فنی مهم
    
    1. مدل‌های Vision‑Language (مثلاً CLIP)
       - دو انکودر دارند: یکی برای تصویر، دیگری برای متن. هر دو به فضای برداری مشترک نگاشته می‌شوند، به همین دلیل می‌توانید تصویر را با متن مقایسه کنید.
       - این مدل‌ها به‌صورت zero‑shot عمل می‌کنند؛ یعنی نیازی به آموزش مجدد برای هر دستهٔ جدید ندارید.
    
    2. ایندکس‌های Approximate Nearest Neighbor (ANN)
       - برای هزاران تا میلیون‌ها تصویر، جستجوی دقیق (exact) بسیار هزینه‌بر است. ANN به‌صورت تقریب‌پذیر نزدیک‌ترین همسایگان را در زمان ms یا µs برمی‌گرداند.
       - FAISS دو معماری مهم دارد:  
         * IVF (Inverted File): داده‌ها را به کلاسترهای coarse تقسیم می‌کند، سپس فقط در کلاسترهای مرتبط جستجو می‌کند.  
         * HNSW (Hierarchical Navigable Small World): گرافی چندسطحی که مسیرهای کوتاه بین بردارها را می‌یابد؛ کارایی بسیار بالا برای فضای high‑dimensional دارد.
    
    3. پایگاه دادهٔ متادیتا (Metadata)
       - علاوه بر بردار، هر تصویر معمولاً متادیتا (آدرس URL، برچسب‌ها، تاریخ، مختصات جغرافیایی…) دارد. این اطلاعات برای فیلترهای دقیق (مثلاً “تصاویر بعد از 2020”) به کار می‌روند.
    
    4. ارزیابی کیفیت جستجو
       - معیارهای رایج: Recall@K, Precision@K, Mean Average Precision (mAP)، NDCG.  
       - مجموعه‌های تست معروف: ImageNet‑R, COCO‑Captions, Flickr30k, که شامل جفت‌های تصویر‑متن هستند.
    
    5. پیاده‌سازی نمونه‌ای ساده (Python)
       python
       import torch, faiss, clip   # pip install torch faiss-cpu clip-by-openai
       model, preprocess = clip.load("ViT-B/32", device="cpu")
    
    1️⃣ استخراج ویژگی یک تصویر
       image = preprocess(PIL.Image.open("sample.jpg")).unsqueeze(0).to("cpu")
       with torch.no_grad():
           img_vec = model.encode_image(image).cpu().numpy()
       img_vec = img_vec / np.linalg.norm(img_vec, axis=1, keepdims=True)
    
    2️⃣ ساخت ایندکس FAISS (در صورتی که قبلاً ساخته نشده)
       d = img_vec.shape[1]                     # ابعاد بردار (مثلاً 512)
       index = faiss.IndexFlatIP(d)             # Inner‑product (cosine similarity)
       index.add(img_vec)                        # اضافه کردن به ایندکس
    
    3️⃣ جستجوی تصویر مشابه
       query_img = preprocess(PIL.Image.open("query.jpg")).unsqueeze(0).to("cpu")
       with torch.no_grad():
           q_vec = model.encode_image(query_img).cpu().numpy()
       q_vec = q_vec / np.linalg.norm(q_vec, axis=1, keepdims=True)
    
       D, I = index.search(q_vec, k=5)           # k=5 برترین نتیجه
       print("Indices:", I)                     # شمارهٔ تصویرهای مشابه
       print("Scores :", D)
       
    
       این مثال فقط بخش extract‑→‑index‑→‑search را نشان می‌دهد؛ برای مقیاس بزرگ باید از IVF/HNSW استفاده کنید و متادیتا را به‌صورت یک دیتابیس (PostgreSQL, SQLite) نگهداری کنید.

    نکات عملی برای شروع پروژهٔ خود
    
    1. انتخاب مدل  
       - اگر می‌خواهید هم تصویر و هم متن را پشتیبانی کنید، CLIP (OpenAI) یا OpenCLIP گزینهٔ خوب و رایگان است.  
       - برای دقت بالاتر می‌توانید از مدل‌های بزرگتر مثل ViT‑L/14 یا ALIGN استفاده کنید.
    
    2. ایندکس‌سازی  
       - در ابتدا با FAISS IndexFlatIP (Exact) برای مجموعهٔ کوچک (چند هزار تصویر) شروع کنید.  
       - وقتی تعداد تصویرها به صدها هزار یا میلیون می‌رسد، به IVF‑PQ یا HNSW مهاجرت کنید.
    
    3. ذخیرهٔ بردارها  
       - می‌توانید بردارها را به‌صورت np.save در فایل‌های bin یا در یک دیتابیس SQLite (ستون BLOB) ذخیره کنید.  
       - برای دسترسی توزیعی، سرویس‌های cloud‑native مثل Milvus یا Pinecone مفید هستند.
    
    4. به‌روزرسانی ایندکس  
       - اضافه یا حذف تصویر باید به‌صورت incremental انجام شود؛ بسیاری از کتابخانه‌ها (FAISS, Milvus) توابع add/remove دارند.
    
    5. پوشش متادیتا  
       - برای قابلیت فیلتر مثل “تصاویر محصول با قیمت زیر ۵۰۰۰ تومان”، متادیتا را در یک دیتابیس رابطه‌ای نگهدارید و پس از دریافت Top‑K از ایندکس، آن‌ها را بر اساس شرط‌های کاربر فیلتر کنید.
    
    6. نکات امنیتی  
       - اگر سرویس جستجو به‌صورت عمومی در دسترس است، دسترسی به ایندکس باید محدود باشد؛ در غیر این صورت افراد می‌توانند با فرستادن تعداد زیاد درخواست، هزینه سرور را بالا ببرند (آسایت حملهٔ DoS).
